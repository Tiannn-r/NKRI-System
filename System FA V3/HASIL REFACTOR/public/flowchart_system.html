State Machine Status Part

Diagram transisi status part di master_stocks: dari Tersedia hingga Done, termasuk jalur Hold, Scrap, dan Rework.

stateDiagram-v2
    [*] --> Tersedia: Part dibuat / diimport

    Tersedia --> Supplied: Dialokasi ke Tray oleh Gudang

    Supplied --> Used: Dirakit oleh Operator

    Used --> Good: QC Status OK
    Used --> Hold: QC Tertahan
    Used --> Scrap: QC Rusak
    Used --> Rework: Perlu Ulang

    Good --> Done: Admin/Gudang ACC

    Hold --> Good: Admin Approve Release
    Hold --> Rework: Admin Ubah Status
    Hold --> Tersedia: Re-register Approved

    Scrap --> Tersedia: Re-register Approved

    Rework --> Good: Dikerjakan Ulang lalu OK
    Rework --> Tersedia: Re-register Approved

    Done --> [*]

Entity Relationship Diagram (ERD)

Relasi antar 9 tabel utama dalam database SQLite sistem Final Assembly.

erDiagram
    users {
        int id PK
        varchar nik UK
        varchar full_name
        varchar username UK
        varchar password
        varchar role
        varchar department
        json permissions
    }

    master_stocks {
        int id PK
        varchar sn
        varchar cs
        varchar part_type
        varchar status
        int allocated_tray_id FK
        timestamp allocated_at
    }

    trays {
        int id PK
        varchar tray_code UK
        varchar pic_warehouse
        varchar assigned_operator
        varchar status
        boolean verified_by_gudang
    }

    parts {
        int id PK
        int tray_id FK
        varchar part_type
        varchar sn
        varchar status
    }

    assemblies {
        int id PK
        int tray_id FK
        int set_number
        varchar pic_assembly
        varchar part15_sn
        varchar part12_sn
        varchar part1_sn
        varchar status
        text reason
        varchar verified_status
    }

    part_audit_logs {
        int id PK
        varchar part_type
        varchar sn
        varchar old_status
        varchar new_status
        varchar action_type
        varchar actor_username
    }

    re_register_requests {
        int id PK
        varchar part_type
        varchar sn
        varchar status
        varchar requestor_username
    }

    assembly_downtimes {
        int id PK
        int tray_id FK
        int set_number
        varchar operator
        text reason
    }

    assembly_wo_history {
        int id PK
        int tray_id FK
        int set_number
        varchar status
        varchar source
    }

    users ||--o{ trays : "manages"
    trays ||--|{ parts : "contains"
    trays ||--|{ assemblies : "produces"
    trays ||--o{ assembly_downtimes : "logs"
    trays ||--o{ assembly_wo_history : "records"
    master_stocks }o--|| trays : "allocated_to"
    assemblies ||--o{ re_register_requests : "triggers"
    assemblies ||--o{ part_audit_logs : "audits"

Ringkasan Tab & Navigasi per Role

Matriks akses modul/tab berdasarkan role pengguna dalam sistem.

No Tab / Modul Admin Gudang Assembly Keterangan
1 Perakitan (Meja Kerja) ✅ ❌ ✅ Card workflow, timer, input hasil rakit
2 Gudang (Supply & Verifikasi) ✅ ✅ ❌ Buat tray, verifikasi, return
3 Print Document ✅ ✅ ❌ Cetak WO, Traveler, QC
4 Laporan ✅ ✅ ❌ 4 sub-tab report + export Excel
5 Master DB ✅ 👁️ ❌ CRUD master stocks (Gudang: read-only)
6 Kelola User ✅ ❌ ❌ Manajemen user & permissions
7 Verifikasi Admin ✅ ❌ ❌ ACC/Decline set, replacement, re-register
8 Production Hold ✅ ❌ ❌ Review hold/rework items
9 Delivery Order ✅ ✅ ❌ Buat DO, PL, cetak PDF
10 Testing Points ✅ ❌ ❌ Kelola poin uji fungsional
📌 Catatan: 👁️ = Read-only (hanya bisa melihat, tidak bisa mengubah data). Akun dengan Custom Permissions dapat dikonfigurasi secara granular melalui menu Kelola User oleh Admin.
✅ Traceability Penuh: Seluruh alur dari Gudang → Assembly → QC → Verifikasi → Dokumen tercatat di database dengan audit trail lengkap, termasuk timestamp, operator, dan riwayat perubahan status.
Dokumen ini dihasilkan otomatis dari Sistem Final Assembly V3 — PT NKRI
